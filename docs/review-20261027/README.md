# Minecraft 影片制作工作流审阅（2026-10-27）

本次结论：保留现有 Python/Java 确定性执行、ReplayMod 母版、声明式镜头和剪辑链路；优先补齐角色绑定、制作依赖与人工审核关卡，再做小范围表演/碰撞修复。暂不全片重拍、不换整张地图、不引入通用物理模组作为主修复。

这是第一阶段审阅交付，不是修复完成或新影片验收。没有修改生产代码、原片、世界或锁定资源。按幕和镜头的执行模板见 [制作模板](production-template.md)，具体试拍见 [试点](pilot.md)，可筛选的时间轴见 [113 条底片及叠加层索引](shot-index.csv)，画面问题见 [问题清单](issues.csv)。

- **V（画面抽样）**：下载字幕版 510 秒原片的审阅副本，98,454,099 字节，SHA-256 为 `3234117a8c9725c502138a70e7f987e02091a9ca502181c2f04cfd1965eaeddf`，与仓库 LFS 指针吻合。每 5 秒抽帧，共 102 帧；另对接触、收包、取衣取样，放大检查关键帧。抽样清单和哈希见 [inspection.json](evidence/inspection.json)。
- **H（假设）**：根据画面和代码提出的根因，尚未用演员轨迹、模型世界坐标或侧面实机机位证明。
- **L（待实机）**：新动作质量、确定性重录、组合模组兼容性、帧时间、阴影/反射、声音与最终正常速度连贯性。

没有逐帧遍历全片，也没有完成全片正常速度听看、三维碰撞实测或新版本 A/B 试拍。不能从本次抽样推出“其他镜头没有穿模”，也不能把贴图、遮挡和三维相交混为一谈。技术成功、缓存 fresh、旧 accepted_spec_digest 都不代表创作验收。

**穿模修复顺序**：先把角色姿态注册表和原始 trace 找回；将部件局部 cuboid 经模型变换、关节变换、根变换转为世界 OBB；广相 AABB 筛选后测 OBB/胶囊与场景 VoxelShape、其他演员、道具的非预期相交。每 tick 检查并覆盖 tick 间扫掠；允许掌心接触/坐椅接触等显式接触窗口，避免把有意接触一律拒绝。随后调整路径/接近方向、肩肘腕锚点、骨长、脚掌支撑和插值；回放正面、侧面、最终机位验证。物理模组最后才进入独立实验。

## 4. 成本与实施优先级

以下为单名熟悉项目工程人员的粗略人日估算，含小规模验证，不含恢复遗失源文件、购买授权、全片创作工时或机器等待；不是测量结果。先用试点建立实测基线，再排全片预算。

| 顺序 | 优化和依赖 | 估算 | 预期收益/可测验收 |
|---|---|---:|---|
| P0-A | 恢复姿态注册表、原始动作计划/trace；核对校园包、运行实例；给缺失文件显式 preflight | 0.5–2天，资料找不到则未知 | 首次预检指出缺项；不进入长录制才失败 |
| P0-B | 镜头/动作段独立审核记录与暂停恢复，技术与视觉状态分开；绑定输出哈希 | 1–2天，依赖A仅实机部分 | 未审核镜头不被当作通过；失败后仅返工段及其消费者 |
| P0-C | 有序资源栈全哈希、rig/动作/环境指纹，分离内容键和路径；建立变更影响预览 | 2–4天 | 改字幕零重录/重导；改相机仅该镜头重导；同内容搬路径零渲染；次级包变化不能漏检 |
| P1-A | 共享事件的接触姿态、扫掠碰撞与步态/关节校准 | 3–6天，依赖A | 试点碰撞与接触可读性通过，重复三次可复现；保留全部剧情动作 |
| P1-B | 局部布景与固定机位三档光影对照 | 1–3天，依赖稳定试点 | 画面变好且预算可承受；只改一个区域，不牵动全片地图 |
| P1-C | 角色/动作资产库、数据驱动动作曲线、资源重定向；优先同 rig | 3–7天，依赖试点 | 新表演用参数及曲线组合，减少每动作一个专用 Java 分支 |
| P2 | 分轨声音、完整逐幕表演与连续性审核、再扩展到全片 | 首个样板1–3天；全片另估 | 音轨不再靠整章旧 MP4 充当唯一源，改时长可定位音频影响 |
| 延后 | 换整张地图、全换动画运行时、通用物理 | 5–15天以上，风险大 | 只有局部方案无法达标且预算确认才启动 |

最高成本风险是改模型/动作后重录大母版、共享事件多处复用导致漏改、靠反复临时脚本调参、直到全片才发现表演问题。先修这些，再优化编码时间。保留编剧、美术、表演设计、终审的人工判断；LLM 用于分镜/表演提案及异常解释，不参与每 tick 操控、命令重试或哈希判定。

每次运行记：人工干预次数与分钟、LLM 请求数/token（若有）、录制次数/时长、渲染分钟、编码分钟、被失效镜头数、复用镜头数、首次视觉通过率、失败分类。预期节省用 `(旧工时−新工时)/旧工时` 实测，不承诺未经测量的百分比。

## 5. 依赖与最小重拍边界

建议在现有 `film-plan → film-shots → film-chapter` 之前增加可版本化的制作依赖描述；不要把新字段直接塞入严格 v3 schema 后声称现有 CLI 支持。先用 sidecar 文档与审核表人工驱动，完成新 contract/model/迁移测试后才接入执行器。

- **录制键**：actor-plan、动作曲线版本、rig/绑定、场景区域快照、道具初态、种子、Bridge/Mocap/Carpet 版本、时间/天气、拍摄起止状态。产出新 replay + trace。
- **渲染键**：replay 哈希、机位与取样区间、资源包栈全部哈希、shader ZIP/选项、Iris/Sodium 兼容组合、分辨率/fps、导出器版本。产出独立镜头。
- **剪辑键**：可见的底片/叠加层、裁切、速度、字幕、图文、音轨锚点、FFmpeg 和字体版本。产出章节→成片。
- **审核键**：输出哈希 + 内容指纹 + 验收表版本；任一依赖变化旧签核失效。机器收据与人工签核分开。

| 改动 | 最小必要工作 | 连带审核 |
|---|---|---|
| 字幕/图文错字，时长不变 | 对应章节剪辑和全片拼接 | 字幕与剧情理解，无须重录演员 |
| 机位/FOV | 该镜头从相同母版重导 | 构图、越轴、边缘露馅、遮挡 |
| 同 rig 的纹理/调色板更换 | 使用该角色的镜头重导 | 服装接缝、阴影和识别度；三段固定插入不能漏 |
| 身材比例/部件结构更换 | 重新适配该角色动作；重录相互接触段，重导使用段 | 周边角色/道具同步状态与所有可见机位 |
| 动作/路径/道具时序 | 重录该连续动作段和有状态耦合的角色 | 引用同事件的所有镜头、章节及转场 |
| 地图局部布景 | 先判断旧 replay 是否已包含旧区块状态；通常重录该区域事件 | 视锥、阴影、镜面/窗景的消费者，不只演员脚下区域 |
| shader/灯光设置 | 使用该环境配置的镜头重导；世界灯块改动可能需重录 | 肤色、接触阴影、频闪及前后镜色温 |

共享母版有 8 个镜头，课堂 S06 母版有 19 个镜头；改变大母版哈希会让所有引用它的镜头失效。以后在 5–10s 可审核动作段记录入口/出口快照和预滚，从段级母版构建；不要随意切割已录的包流并声称可独立复现。

共享街头事件被 S01/S02/S03/S05/S06 复用。`SH_phone` 更改须扫描底片和 overlay，不能只查 timeline；`SH_full` 是剧情真相揭示，换接触动作必须保证短视频与全景仍是同一事件的同一次表演。仅换机位时不重新表演。全遮挡的底片可作为后续优化，但透明度、淡入淡出、音轨、保留长度都证明无贡献后才可裁掉计算，不能直接删镜头。

动画制作流程：建立每角色 rig-profile（部件、父子关系、pivot、原始骨长、UV、手掌/脚掌/道具锚点）→坐标与角度单位归一→作者曲线重定向→按实际路程驱动步态→站立足锁定、摆动足抬升→接触 IK 与允许接触窗口→动作间保姿过渡→20tick执行与30fps导出都检查。肘膝弯曲需端帽/合理搭接，不能非均匀缩放手臂来遮洞；关节轴错位先修 rig，再修 UV。

表演保留完整意图：陈师傅先发现危险、快速伸手、承重、观察老人反应再松手；老人先失衡、护腿、迟疑，再借力站起；路人先举手机、受惊停顿、放下手机、参与帮助。听者视线与呼吸轻动、嘴型及停顿应服务对白；不机械地每几秒加摆手，不以删除推/扶/收拾动作降成本。

## 7. 地图、资源包与光影候选

优先使用现有 CityCampus、Northfield 建筑及原版材质补景。来源边界见 `ASSET-CREDITS.md`：Northfield 标 CC BY-NC 4.0；城镇和角色设计没有独立开放授权，限现有非商业样例范围，扩大传播/商业用途需另核许可。已有 ZIP 不代表全项目地图资源全部获自由再分发权。

| 方案 | 作用与成本 | 影响范围 |
|---|---|---|
| 原地图局部布景，首选 | 0.5–2天/样板：课堂添学生分布、黑板内容与学习用品；工人休息室添水壶、工具、工衣/通知；街道增加有因果作用的围挡/警示、前中后景；避免随机堆物 | 保持演员路径与主要地标；修改区域、窗景和阴影可见镜头重录/重导 |
| 原场景调整机位/桌高/站位 | 0.5–1天/样板；S07 降低桌沿遮挡，S04 让坐姿和手部可辨；街道把扶人接触侧向展示 | 仅改相机可重导；改桌/站位则关联动作需重录 |

| 完全新地图 | 暂不选，许可、资源包依赖、版本转换、角色路线和全片地理连续性代价高 | 先做同镜头预演证明局部补景不够，再评估 |

光影保持同一表演母版、相机、时刻、天气、视距、分辨率与曝光；先改布景，再比较光影，避免两个变量同时变化。

试拍记录 GPU/OS/驱动、Java/Fabric、所有 JAR SHA-256、世界/区域哈希、资源包顺序、shader ZIP/配置哈希、视距、阴影分辨率、曝光/AA、输出设置。冷启动后重开回放、前后跳时、重导三次，确认无部件丢失/插值异常/阴影闪烁；测录制tick稳定性、渲染秒/帧、峰值内存及人工复核耗时。实时fps与离线成片30fps分开评价。选型后才写入正式资源锁，候选表不伪装已验收配置。
