# 按幕、镜头和动作段制作模板

此模板是创作与执行的交接文件，**不是现有 CLI 可直接读取的新 schema**。现有 schema 是执行白名单；新增字段先保留在 sidecar，未来新增 contract/model 后再自动编译。没有现场确认的坐标、版本或授权填“待核”，不能靠占位值通过发布检查。

## A. 幕级规划（每幕一份）

- 幕 ID / 名称 / revision / 负责人 / 审核人 / 日期：
- 剧情目标：人物想做什么、遇到什么阻力、本幕结束改变什么。
- 观众已知/本幕揭示/刻意未知：明确不能提前泄露的信息。
- 起止状态：角色情绪、位置、朝向、服装、手持物；前后幕连续性。
- 预计总时长、声音风格、节奏；关键对白与事实依据。
- 场景与允许修改区域：世界 ID、维度、区域边界、入口/出口；快照哈希。
- 资产清单：角色/rig、动作、道具、地图、资源包、shader、声音、字体；版本/哈希、来源、许可、署名、可否公开分发。
- 依赖幕/共享事件：引用同一回放的哪些视角；哪些事件必须一致。
- 镜头顺序表：镜头 ID、段 ID、时长、剧情功能、起止状态、转场、审核状态。
- 幕级完成条件：每个可见镜头获签核、衔接审核、剧情/声音复核。

现有草稿可按以下结构整理，但这是本次根据字幕/图文/配方概括，须由创作者确认后冻结：

| 幕 | 现有全片区间 | 剧情任务与特别审核点 |
|---|---|---|
| S01 | 00:00–00:55 | 课堂布置新闻核查；建立A与周然立场。收包动作及手机插入须完整可复现 |
| S02 | 00:55–01:40 | 街头片段及首次传播；短视频保留误判空间，但不能靠身体穿插制造歧义 |
| S03 | 01:40–02:55 | A接触、加工、转发信息；观众能区分原视频、标题、评论与A自己的判断 |
| S04 | 02:55–04:15 | 展示陈师傅受到影响；电话、坐姿、放手机要有真实情绪节奏 |
| S05 | 04:15–05:30 | 全景补足落物背景；与S02必须是同一物理事件，不能另演出矛盾版本 |
| S06 | 05:30–07:10 | 课堂区分观察与解释；减少仅靠固定站姿说明，补听者反应和停顿 |
| S07 | 07:10–08:15 | 修正、回应及余波；收包/离开与消息打断要连贯 |
| credits | 08:15–08:30 | 作者、资源来源、版本和许可；核对实际使用清单 |

## B. 镜头卡（每镜头至少填写）

| 字段 | 内容 |
|---|---|
| 身份 | 幕ID / 镜头ID / 动作段ID / revision / 替代旧镜头 / 是否共享 |
| 剧情 | 目的、关键情绪、必须看清的动作、不能揭示的内容 |
| 场景 | 世界/维度、布景快照、操作边界、光照时间/天气 |
| 演员 | actor_id、model_ref、rig版本；每人XYZ、yaw/pitch、起始姿态/手持物 |
| 动作时间轴 | 对每个角色逐步列动作、起tick、时长、路径节点、朝向/视线、对象、抓取/释放/承重点、终态 |
| 摄影 | 景别、XYZ、yaw/pitch/roll、FOV、关键帧、插值、运镜、构图安全区、轴线、对焦/曝光 |
| 剪辑 | 预计时长、入出点、前后留白、转场、图文/字幕/竖屏插入、相邻镜头状态 |
| 声音 | 对白/呼吸/脚步/衣物/道具/环境/音乐，source、in/out、事件锚点、声像/电平目标 |
| 资源 | 地图区域、全部演员/动作/道具、资源包栈顺序、shader/配置、运行版本；全部有哈希与授权 |
| 执行 | 前置条件、恢复初态、预滚、录制、导出、检查点、失败后的清理/重试策略 |
| 验收 | 技术、几何、表演、构图、声音、连续性分别列判据和审核人 |
| 失效范围 | 修改哪项导致重录哪个段、重导哪些镜头、重编哪些章；共享引用列表 |
| 证据 | take/replay/trace/output/审核记录路径与哈希，issue ID，结论与下一步 |

动作步骤表（所有演员时间轴连续，未行动时显式 idle；路径每段落入允许区域）：

| step | actor | start_tick | duration_ticks | action | XYZ路径/目标 | yaw/视线 | 互动对象/接触窗 | 结束状态 | 通过条件 |
|---|---|---:|---:|---|---|---|---|---|---|
| 填写 | 填写 | 填写 | 填写 | 必须是当前支持动作 | 每节点坐标及地面 | 度；明确头/身区别 | 目标actor/prop及tick | 根位置/姿态/道具 | 可测且可看 |

20 game ticks = 1s；30fps输出中一个tick等于1.5帧，不要当成每tick一帧。原生回放时间使用 ActorService trace 的 replay_timestamp_ms 对齐，不能用录制系统日期直接推算。动作为连续事件时，段切换需保存入口/出口状态；不能在任意中间tick从默认站姿启动。

## C. 与现有结构化计划的映射

| 制作意图 | 已有执行位置 | 仍缺什么 |
|---|---|---|
| 演员起点、朝向、动作区间、互动对象 | `contracts/v3/actor-plan.schema.json`；注意其内容 schema_version 当前为1；`actors.py` | 角色绑定文件、可配置rig/曲线与碰撞诊断 |
| 相机、母版、tick、包栈、fps | `contracts/v3/film-shots.schema.json` | 全部渲染依赖哈希、角色参与/区域可见性索引 |
| 时间线、图文/字幕/声音 | `contracts/v3/film-chapter.schema.json` | 剧情目的、人工验收、分轨素材来源 |
| 各章顺序、输出路径 | `contracts/v3/film-plan.schema.json` | 录制任务图、审核暂停恢复 |
| 自动媒体证据 | 原有 receipts、journal、manifest | 不替代新的审核单 |

例如“缓慢转身，先看目标再转肩”不是简单 `look_at` 一定能满足的效果；若现有动作不能表达，标为需实现的曲线，不准执行 Agent 擅自简化成瞬间转向。复杂表演不能为了通过 schema 而删掉。

## D. 从规划到交付的关卡

1. **规划冻结**：创作者确认剧情、按幕镜头卡、动作与资源。程序校验引用/哈希/时长/连续性；输出影响清单，人工检查创作意图。日常编排不需要LLM重新推理。
2. **开机预检**：实例、版本/能力、世界/区域、资源栈、binding、磁盘、FFmpeg、输出不存在；明确录制/渲染哪一种任务。缺证据就 blocked。
3. **单段排练**：恢复已登记初态，记录预滚和状态，执行5–10秒段；记录trace/碰撞诊断。未知操作状态先查询journal，不能盲重试导致重复演员/道具。
4. **单段审看**：导出正常速度片段和关键帧，技术检查后进入 needs_review；人工看动作、接触、声音与意图。approved 才推进依赖它的下一段；rejected 定位原因。无依赖的其他规划可以继续。
5. **单镜头导出与复核**：从获准母版导出最终机位；排练通过不能代替构图通过。旁边诊断机位作为证据，不混入正片。
6. **有界重拍**：分类为路径/姿态/模型/布景/机位/剪辑/声音；定位最小段及状态依赖，写新take，不覆盖旧文件；预览影响清单后重做对应层。保留失败样本和根因，避免同类问题重复LLM讨论。
7. **按幕验收**：合格镜头组装后看轴线、视线、道具接续、时空、反应与停顿；共享事件跨幕对比。修改输出即撤销关联旧签核。
8. **全片验收**：技术检查 + 全片正常速度带声音审看 + 关键接触逐帧 + 字幕/署名/版权核对。双版本画面/声音按预期一致；成片只有全部通过才发布。

建议状态：draft → plan_approved → preflight_passed → recorded → technical_pass → needs_review → approved/rejected；另有 blocked/unknown。现有CLI尚未实现这套状态，不可把文档当作已经生效的强制门禁。实施前由制作负责人逐项执行，避免直接运行大范围 run_master 越过人工关卡。

## E. 审核记录模板（独立 JSON sidecar）

以下是文档模板，空值表示未审核，不可直接作为批准凭据：

```json
{
  "review_format": "proposal-1",
  "chapter_id": "S02",
  "shot_id": "PILOT_SUPPORT_FRONT",
  "segment_id": "PILOT_SUPPORT",
  "take_id": null,
  "spec_digest": null,
  "output_sha256": null,
  "reviewer": null,
  "reviewed_at": null,
  "normal_speed_watched": false,
  "audio_listened": false,
  "technical": "pending",
  "geometry": "pending",
  "performance": "pending",
  "composition": "pending",
  "continuity": "pending",
  "sound": "pending",
  "decision": "needs_review",
  "issues": [],
  "evidence": [],
  "retry_scope": []
}
```

问题记录必须包括：issue_id、证据等级、文件/哈希、章/镜头、全片/章内/素材时间、帧号或tick、角色/部件/物体、预期与实际、根因置信度、截图/轨迹、修复版本、影响列表、复验结果。审核人不能留空却写approved；程序不得从 technical_pass 自动生成批准。
