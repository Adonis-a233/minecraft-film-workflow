# 审阅后代码修复（2026-10-27）

本次修复面向审阅报告 P0-B、P0-C 的可离线验证部分。未替换世界、资源包、回放、电影素材或原始姿态；没有完成实机动作/画面验收。

## 已实现

- 镜头指纹第 2 版包含全部启用资源包的顺序及哈希，修复更新次级包 pin 后误复用旧画面的问题。未启用包变化不影响镜头。
- 去掉镜头内容指纹中的输出路径；搬迁时验证新位置的哈希，有收据时还要求与收据哈希一致，不回退使用旧位置。
- 增加可选 `render_dependencies`，允许 pin shader、选项和渲染版本锁文件。缺失/变更会失效并阻止导出。声明锁文件不等于已验证游戏中的实际启用设置。
- 镜头、章节、成片都有独立人工审核记录；自动化技术收据不会变成人工批准。正常速度观看、审核人、时区时间、五项检查和备注均须显式填写。
- 新镜头/章节完成即暂停；被拒绝或未审核时保持暂停；同一命令可恢复。章节需先通过相关镜头审核，全片需先通过章节审核，全片技术完成还需终审。
- 审核绑定内容规格及输出哈希；上游规格变化会撤销下游旧批准，即使新输出字节恰好相同，也需重新审阅，但可避免无意义的重复编码。单纯镜头路径搬迁可复用审核。
- 审核记录追加保留，审核与执行共享计划锁；执行在取得锁后生成报告，避免用等待锁前的旧状态。
- 黑帧检查进程异常退出时拒绝发布，防止把“未检查成功”当成“没有黑帧”。
- 修复进程锁回归测试写死 Windows 依赖路径的问题，使用当前虚拟环境解释器运行子进程。

操作方式与审核 JSON 格式见 [总控说明](FILM_MASTER.md#2026-10-27-修复内容指纹与审核关卡)。

## 真实旧稿预览的额外阻塞

实际运行旧稿 `film-master-preview` 时，顶层 pin 校验拒绝 `shots-manifest.json`。核对发现，9 个 pin（镜头清单与 8 章配方）保存的是 CRLF 文件的 SHA-256，仓库 HEAD 和本机文件则为 LF；将文件换为 CRLF 后计算的哈希均与声明相符。这是已有的字节级换行差异，本次没有修改这些资产或放宽哈希校验。

后续建立新版本计划时，应先统一并固定这些文本文件的换行，再按实际文件更新所有相关 pin；只更新顶层 pin 不保证 ASS 等下层输入的哈希也相符。不能把跨平台换行迁移与影片视觉批准合并。旧第 1 版镜头指纹也不会被静默重算，须核实完整资源栈后进入新版重导流程。
