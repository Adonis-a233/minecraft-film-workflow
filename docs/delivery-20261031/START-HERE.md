### 一次性格式与UV适配（预算10分钟，最多两角色代表）

七图都是64×32、4px经典手臂。保留AP/AQ实际骨架、动作、坐标和缩放；不能为了贴皮肤换到Alex细手臂后重测整套动作。

先核对目标模型纹理UV：支持旧格式就按其明确设置加载；目标为64×64时使用现有可靠的legacy-skin转换器，将原32行保留、补出左右独立肢体且维持透明外层。**不能把64×32直接拉伸成64×64，不能仅扩画布而忘记左手左腿。** 转换后另存`<role>-classic64.png`，原图与变换记录保留。

选教师（白袖）和陈（反光背心）各取静止/屈肘/走停三个关键姿态，一次正侧背检查；接缝、脸和左右肢体正确后，同格式其余五人只检查身份与静止UV。若目标Emoticons模型并非标准UV，直接使用模型已有UV布局做明确重映射并记录差异，不把模型不匹配归咎于图片分辨率。达不到映射条件时保留皮肤文件并报告具体UV岛，其他镜头队列继续。

眼睛/嘴模型暂不叠加到已有脸上，避免双眼双嘴。对白先按已支持的轻头动/口型通道工作；有可用脸部绑定再匹配，不能临时重建表情系统。工地安全帽如剧情卡要求，使用现有项目道具单独绑定头部，不在PNG外随意涂抹，也不因没有帽道具删掉要求。

## 4. 预设直接怎样做

读取`action-presets.json`。12个预设覆盖静听、走停、原地转身、看手机、展示手机、收手机、收书入包、取衣、推离避险、扶起、单件拾物和起床。它们写出了每个阶段的秒数、接触对象、所有权切换及出口状态；只需要接入当前Windows实际骨骼和道具ID。

- AP/AQ已通过的root/步态/过渡原样作为共享基础，真正源Film与哈希从Windows现有收据取得，不根据文字重造近似品。
- 手机只校正BodyPart局部rotate：握点、AS手臂/头曲线不动；已诊断世界+Z为脸侧，仅适用于该原模型yaw0配置。两轮静帧+一次短动态，15分钟上限；失败只阻塞持手机镜头。
- 新接触动作按手目标/脚支撑约束编排，用现有IK与骨骼长度，不伸长肢体、不换物理Mod。动作库作为运动来源，剧情接触关系按预设事件补齐。
- 所有事件预设秒数是制作默认值；必须服从Windows已经更新的共享事件锚点。不能为了套5秒拾物而压缩旧3040ticks实现。新制作一个明确的单件拾物序列，每个物件唯一所有者；物件多则顺序复用并延长事件预算。
- 布局、动作、附件、相机分别锁版本。机位改变只重导镜头，手机rotate改变只更新相关镜头；换皮肤但骨架不变只补UV验证，不重解足底。

若一个预设无法映射，输出缺失的准确骨骼/道具/通道及已尝试输入，不输出“需要继续研究动画”。用同组其余可执行镜头继续生产，不写新框架。

## 5. 镜头和时间规划：Windows负责现场解决，我给规则

`shot-bindings.json`将85张原镜头卡的动作、相机、资源、声音和验收集中成单一读取入口，减少Agent逐文件重读。它保留原规划时间，**不覆盖Windows新时基**。

Windows按以下固定规则解决已报告时间差异，不需重新询问创作方向：

1. 以当前已修改且用于执行的shared-event为事件E时间唯一来源。确认它确实表示完整动作，而非仅标题变更。
2. 为每条共享事件消费者写E入点/出点和幕内入点/出点；S02拾物如果改为E27.5开始，S02_07动作正文、标题、时长、索引同步更新。先平移受影响的后续镜头，不平移无依赖的前段。
3. 不缩短必要接触。若幕总时长容纳不下，先减少该幕后期UI多余停留，仍不足就明确增加幕长，并更新后续全片偏移；不得为维持510秒改变动作物理节奏。
4. S05监控引用同一E母版，更新连续时钟与各卡相对时间；新片音频根据台词语义对齐，不能盲用旧幕偏移。
5. 编译前核对标题、正文、shot-list、planning-index、实际Film五者一致。将差异与新总时长写time-map-resolution.json，保留旧版本；无矛盾时直接执行，不再等待规划端给出虚构的Windows文件。

拍摄顺序仍为已有UI先交付 → 同教室无手机镜头 → 手机镜头 → 其他室内 → 共享接触事件及引用。相同场景一次加载，多镜用参数驱动；任何镜头通过不代表其他镜头自动通过。

## 6. 配音全部优先使用你已给的原片声音

主源：`assets/audio/full-film-v10-continuous-48000-stereo.flac`，510秒、48kHz、双声道，SHA256见锁。已完整解码检查。它是仓库旧片配套无损音轨；若Windows另有用户指定且不同于这份旧片的视频，以那份用户原视频为准，并记录差异，不能假称两者相同。

`audio-cues/index.json`给出66句台词、原片时码、裁切文件、文件内起点和哈希。按台词文本匹配镜头，不按文件排序机械拼接。先复用这些原声，删除候选里的临时Microsoft TTS引用；没有对应原声的台词记缺口，禁止私自补AI声音。

这些是混合音轨片段，可能含环境、音乐和重叠声音：不做“提取纯人声成功”的宣称。不同时叠加整幕原混音和逐句cue，以免双声。最省工路线：时序未变的幕直接用原片对应整段音轨；重排镜头按cue移动，并审听交叉淡化与环境连续性。动作音与对白重叠无法拆开时，优先让动作贴原音时间；不强行拉伸对白。时长改变后的空白用实际已有环境声，不循环人声。

## 7. 恢复提示词与30分钟成果

Windows：现在按用户恢复指令继续。先保存本地改动并fetch影片分支，只取本交接及ready目录，不合并main的资产删除。

- 0–5分钟：核对锁和已有素材；找到原片声音cue，不再调研皮肤/光影/动作库。
- 5–15分钟：处理已有S05_07–10或S02_09–10候选，按原音替换临时声并核对文字与边界；若原音无对应句，先用另一组有完整原音的候选。
- 15–25分钟：导出正常速度可审看片段；同时用已下载教师/陈皮肤做一次代表UV静帧检查。不为出第一个片段重跑手机实验。
- 25–30分钟：交MP4、真实shot_id、声源、输入版本、待审项；继续按镜头队列。30分钟交片段不是声称全片已验收。

全片继续推进到完成；只因真实缺项阻塞具体消费者，不因需要人工审核停止所有独立工作。原生导出、画面和声音验证分开，所有approved必须有真实审核对象与记录。

## 8. 备选方案

| 问题 | 立即执行的备选 |
|---|---|
| legacy皮肤格式不被模型支持 | 一次准确UV/格式转换；别拉伸图片或换骨架。该角色暂记待审，独立UI继续 |
| 模型或手机局部方向两轮失败 | 保留输入，输出完整父变换/目标轴；转无手机镜头，不再重录基础走路 |
| shader官方源不可达 | 直接复用Windows已有且哈希匹配的r5.9.3；无匹配文件先做无光影诊断，不把诊断当最终画面 |
| 新摆件和原场景冲突 | 跳过对应摆件并记录，不改演员和镜头轴线；主机位有层次即可 |
| 某句原音没有/混音无法切净 | 保留该句待处理，优先另一完整原声片段；必要时按整段原声节奏调整画面，不生成新配音 |
| 联系动作在默认秒数内不自然 | 延长共享E事件并同步消费者；不加速人物或删动作 |
| 30分钟未能交片 | 写明缺的具体文件/命令失败；下一轮先解除这个直接阻塞，不新增研究任务或虚报完成 |
