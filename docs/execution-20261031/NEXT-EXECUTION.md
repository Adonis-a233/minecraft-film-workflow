## 1. 依据与结论

实际阅读了本目录 evidence 下两份Windows报告，未取得AZ/BA/AX视频、源Film、适配器源码或用户审核原始文件。本轮不是新的视觉验收，数值结论和用户批准范围来自执行报告。旧SMB挂载是迁移目录，没有据此宣称已检查Windows最新工作区。

- **冻结AP/AQ**：报告记录用户原话“排练动作可接受”，涵盖机器人纹理下步态、停步、过渡和垂直运动。整数root键与一致插值已经解决AO问题；同一输入不再重建足底测量系统，也不再重测AA至AO旧失败。
- **手机问题局部化**：现有证据是位置数值对齐但局部屏幕朝向错误。面朝世界+Z（该模型yaw=0配置）；renderer与BOBJ缓存的Y180必须作为完整变换链理解，不能再只取其中一个翻转。
- **保留AS原手臂/头部曲线**，保留零虚拟骨骼原点与已确认地面修正，只校准手机BodyPart局部Euler rotate。不改全身yaw、步态、握持位移或镜头来掩盖朝向问题。
- **BBS原生导出作为当前执行路径**；已失败的ReplayMod人物持久化路线不再占用本批预算。
- **已有UI不是零产出**：S03/S07、S05_02/07/08/09/10、S02_09/10已有候选。先登记与审看已有候选，不重建相同内容。临时系统声音不作为最终配音。
- **正式人物美术仍阻塞**：机器人动作通过不等于最终角色通过。不能以提速为由将机器人镜头算成最终片。

“有规划就能输入坐标”在模型、动作、附件、时间映射已锁定后成立。本次主要缺口是这些一次性标定没有冻结成可复用预设，测试失败没有缩小影响范围，镜头队列又被共用门槛整体堵住。以下流程针对这三个问题，不承诺未经实测的自动化能力。

## 2. 恢复后的首轮预算：90分钟内产生镜头级交付

预算是排程上限，不是验收降标；到时登记具体阻塞并转入独立工作。机器导出可继续运行，但Agent不得在等待期间重复改同一组参数。发生明确崩溃或损坏时立即停止相关运行。

| 时段 | 工作 | 必须留下的产物 | 超时备选 |
|---|---|---|---|
| 0–10分钟 | 保存现有改动，登记AP/AQ和当前手机输入；检查已有UI候选 | 输入路径/哈希、审核范围、可用入口、队列 | 缺某文件只阻塞消费者，不全盘扫描机器 |
| 10–25分钟 | 手机局部旋转校准：静态关键姿态，最多两轮 | 带轴向/屏幕正反标记的正侧视静帧、局部rotate数值 | 手机相关镜头挂起，转UI与无手机镜头；保留失败记录 |
| 25–35分钟 | 只有静帧通过才做一次短动态验证；整理已有UI审核片 | 手机抬起/保持/收回的必要短段，或UI连贯审核片 | 不为手机重新跑完整行走/思考试段 |
| 35–90分钟 | 直接处理下述首批镜头，复用场景和动作 | 至少一个有真实shot_id的候选交付包及台账；若资源阻塞，交付具体编译输入与缺项 | 优先完成已有UI候选与字幕/声音衔接；不继续加试验字母编号 |

## 3. 手机校准的明确执行边界

先从实际ItemForm及完整骨骼变换取屏幕法线n和屏幕上方向u；为诊断临时加“屏幕正面/顶部”标记。目标是屏幕朝角色眼睛，顶部朝正确握持上方，摄像头朝被拍对象（拍摄姿态时）。不同用法分别锁预设，不能把“给观众看屏幕”和“角色看屏幕”混为一个方向。

在握持关键帧冻结动画，用完整父变换的逆矩阵把目标方向转到附件局部；对方向使用正确的线性/法线变换并处理缩放，再按实际BodyPart Euler顺序求旋转。**这里不提供未经源码与画面核实的±90/180度常量，也不臆造Euler顺序**。执行端必须从现有实现读取，不重新设计骨骼系统。单个法线不足以确定roll，需要同时校验顶部方向。

第一轮：根据变换推导一个候选，正面与侧面截帧。第二轮只修首次证据指出的剩余轴/roll。通过后一次短动态检查，无须每轮导出14秒1080p正背面两片。若数值指向正确但画面相反，检查模型屏幕面的定义/材质正反及额外局部变换，不再次翻转整个人物。

当前AZ/BA原片保留用于诊断。约14秒不是手机方向试验失败的充分理由；能定位握持阶段并看清屏幕朝向就有诊断价值。原先固定29–389帧裁切继续禁用。若仍需五阶段12秒对照，使用实际Film阶段与录制时钟映射生成一次；正式镜头按自己的镜头卡时长裁切，不强制12秒。

## 5. 将“动作套上、站位输入”落实为一次编译、重复执行

复用Windows已有适配器，首先记录真实入口。以下是应落实的数据职责，不是声称仓库已有这些接口；禁止将描述性JSON直接交给未知运行器。

1. **角色动作预设**：模型和骨架哈希、源动作、已接受root曲线/插值、局部附件变换、适用姿态、审核范围。AP/AQ成为版本化预设。更换皮肤但骨架不变，只补UV/外层检查；换骨架必须重新验证受影响动作。
2. **场景锚点**：世界副本及版本、教室/宿舍/街道局部原点、一次实测站位与朝向。镜头使用局部路径加场景变换，不能让LLM逐镜猜世界XYZ。
3. **镜头实例**：shot_id、预设引用、起止状态、局部路径、朝向、镜头卡时间、相机、光影、道具、声音与输出。已有台账保留，不另建互相矛盾的完成状态。
4. **程序编译与预检**：检查所有引用、路径、时段和已知接触约束；产生实际BBS Film及实际运行命令。先编译同场景全部可执行镜头，预检失败仅隔离依赖项。
5. **执行与恢复**：逐镜保存输入哈希、Film、输出、关键帧与状态。一个场景只启动/加载一次，镜头间按入口状态恢复。批次内逐镜检查，不让一次失败丢失整个批次。
6. **变更影响**：手机rotate只重建持手机镜头；相机改动重新导出该镜头；字幕/音频改动只重做后期；共享表演变更才使全部消费者失效。绝不因手机修正重测无手机AP/AQ。

优先用现有脚本增加预设和批次参数，首轮不建立新的通用框架。一次适配开发预算30分钟；仍缺接口则交付明确错误和输入输出，使用已成功的单镜入口串行执行独立任务。

| 阻塞 | 可执行备选 | 不能据此宣称 |
|---|---|---|
| 手机两轮仍错误 | 冻结该附件版本、报告完整变换证据，执行P0/P1 | 手机已通过或可以删掉手机动作 |
| 最终皮肤仍403/原图缺失 | 规划端继续交付来源、原图、身份映射；执行端完成UI、世界和一次构图排练 | 机器人可充当正式角色；重新反复测试机器人能解除美术阻塞 |
| AP/AQ真实预设/审核文件找不到 | 按报告路径定点找源Film和user-review-ap-aq.json；缺项登记 | 仅凭报告复刻近似参数后继承原审核 |
| 新模型导致旧动作失效 | 为该模型新增一次代表动作验证，原模型镜头继续 | 所有旧通过项永久失效或不同骨架免测 |
| 光影人工对照未定 | 以AP已用r5.9.3固定制作候选，提交既有AP/AR对照一次 | 光影美术已最终批准；可随意升级到最新版本 |
| UI临时配音未替换 | 先交付无临时声的画面母版与独立音轨占位清单 | 静音或临时TTS为最终声音 |
| 时间规划冲突 | 隔离该镜头及消费者，提交当前shared-event/S02/S05和索引差异 | 直接平移所有动作或缩短拾物已获授权 |
| 原生导出帧边界不稳定 | 一次标记/预滚诊断；必要时把边界修复作为独立技术任务，其余UI后期继续 | 凑够360帧就是五阶段完整 |
| 只有人工审核未完成 | 独立候选队列继续，已制作项记needs_review | 自动填approved，或停止所有素材准备 |

## 7. 验收与进度衡量

进度按真实镜头ID计：已编译、已有候选、待审、已批准、阻塞。试验字母次数和脚本数量不作为进度。首次恢复后每30分钟记录一次：时间花在编辑/导出等待/诊断/审核哪一项，完成了哪些shot_id，重做原因是什么。无需每帧LLM判断或每次输出长计划。

通过条件保持镜头卡要求：正常速度表演、穿模、构图、画面连续、声音。已有通过数值作为回归参考，不能无限压低误差追求机器精度；只有可见缺陷、已知碰撞或新输入变化才重开该项。审核与交付必须保留真实范围。
