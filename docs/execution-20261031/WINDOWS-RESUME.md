## 30分钟执行顺序

- **0–5分钟**：登记现有AP/AQ预设与已生成UI素材；只核对定点路径，不重搜资源、不重新安装工具。AP/AQ既有批准范围冻结。
- **5–10分钟**：先处理已存在的S05_07–10连续16秒UI候选；核对文字、时长、音轨和边界。若缺文件，则使用已有S02_09–10的12.5秒候选。不得为这一步启动Minecraft。
- **10–20分钟**：修复这个片段中实际发现的缺陷，复用已有图文与剪辑入口。已有候选无缺陷就直接进入审核包，不为显示工作量重复渲染。临时TTS明确标注；没有最终声音则同时列出缺失音轨，不报最终声音通过。
- **20–30分钟**：交付正常速度MP4、镜头ID清单、输入版本、片段状态及剩余问题。将所有已有镜头登记为现成/待审/需重拍，不让时间继续消耗在全局测试。

片段必须有实际内容，不能只交参数或进度文档。若连上述两组已有文件都缺失，立即报告确切缺失路径，并用已成功入口生成其中一组；真实失败必须说明，不伪报完成。30分钟是执行预算，不是允许伪造审核的期限。

## 此后连续推进

先交片段，再进行手机修正。手机只改BodyPart局部rotate，保留已对齐位置、AS手臂/头部曲线、AP/AQ步态；最多两轮静态正侧视校准、一次短动态确认，总人工处理预算15分钟。失败挂起手机相关镜头，转无手机镜头和UI。不要继续生成字母序号的整套14秒试拍。

采用NEXT-EXECUTION中的P0/P1/P2/P3镜头队列。同场景站位和机位一次标定，动作作为版本化预设，程序填写镜头参数并编译实际Film；每个镜头保存证据后再推进。已有脚本缺能力时最小补齐，不开发新框架。机器人纹理仅作最多一次布局排练，不批量渲染成正式人物画面。
