## 2. v11执行包最低组成

下表是必须补齐的交付物，不声称当前这些文件已经生成。

| 内容 | 必须具备 |
|---|---|
| 环境与资源锁 | 实例/世界身份、精确版本、哈希、资源栈顺序、实际光影开关/参数 |
| 场地锁 | C/D/W/E世界坐标变换、相机、地面/桌椅/道具锚点、边界、验证截图 |
| 演员动作计划 | 合同校验通过的actor-plan/已登记动作引用；口型及初末态；冲突矩阵全部有处理结果 |
| 录制任务表 | 每个take的输入、依赖、状态恢复、母版输出、超时/失败策略；一个明确运行入口 |
| 镜头与后期计划 | 每镜映射母版/时间/相机，UI单独后期，七幕章节＋片尾＋全片配方；生成前不可伪造母版哈希 |
| 审核/恢复记录 | 机器结果和人工判断分开，待审暂停为正常状态，问题影响范围可追踪 |

先形成“录制运行包”；回放与新输出产生后再填真实哈希形成“导出/剪辑运行包”。不要求开录前存在尚未产生的母版哈希，也不能拿旧母版冒充新表演。

## 3. 开机后的放行顺序

1. 原实例启动、只读Bridge检查，确认当前世界、玩家和录制/导出能力。
2. 在世界副本恢复一个短段初态；录制→保存→回放→导出，保持角色/道具正确。正常速度及关键帧审看。
3. 同一回放前跳/后跳后再次导出；检查动作、嘴型、散落物、光影状态是否一致。
4. 试一次正常暂停/恢复；模拟工具连接中断时只查询既有operation，不重复生成演员或录制。保留任务和现场证据。
5. 所有硬阻塞关闭才开始批次。若仍有缺项，停在blocked并列出具体文件/动作，不让执行Agent临场改故事、装Mod或换地图。

保存输出盘空间、实际每秒视频导出耗时、GPU/内存峰值后才估算全片耗时。桌面会话保持游戏可运行，关闭系统睡眠；远程断开、锁屏和显卡行为用实际机器验证，不承诺后台或无界面可录。

## 4. 无人值守与审核的实际边界

当前默认：自动完成一个可检查镜头→needs_review→人工正常速度审看→登记真实审核→恢复。离开电脑时会停在待审，这不是崩溃。

如果用户希望整夜不经人工一路录素材，需要另行冻结“只产出待审候选”的批处理模式，并实现独立任务失败隔离；仅无状态依赖的候选可以继续。其余剧情衔接/接触/共享事件仍受未通过上游约束。这个模式当前没有交付，不能通过自动填写审核JSON、关掉校验或无限重试实现。

当发现几何/表演问题：修动作并重录相关段；机位问题：复用合格母版重导；声音/UI问题：重做对应后期；共享事件变化：刷新全部手机/监控消费者。未经审核的素材永不标成最终成片。
