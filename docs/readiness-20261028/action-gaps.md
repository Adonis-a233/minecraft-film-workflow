# 新规划与现有动作合同的冲突矩阵

依据：`agent/src/minecraft_film_agent/actors.py`、`cinematic-bridge/.../actor/ActorPlan.java` 和七幕规划。这里列的是静态约束；通过合同也不表示视觉通过。20 ticks/秒。

| 动作/场次 | 现有约束 | 新规划要处理的事项 |
|---|---|---|
| 拾物 / E、S02/S05 | 仅filmer，一次，固定3040ticks；固定起始偏移与终点；Java亦有约束 | 与4秒拾物段不相容。先定义一次拾取的完整短动作，再定义多件拾物循环及道具所有权；保留路人停录后帮助。不能仅改duration校验而不改轨迹 |
| 取外衣 / S03 | 仅A，60–100ticks；此前所有step只能phone，此后只能hold_coat；目标有严格可达范围 | 不能同一take先walk_to走到衣服或随后walk_to出门。复用时从已经到达取衣点开始；另段离开必须保留衣物/手机状态。若做不中断长镜就需扩展实际实现 |
| 陈站姿收包 / S07 | 仅陈，固定160ticks=8秒，前后只能idle | 不能直接把接电话、站起、收包、走门边塞入同take；动作前后余量另计，核对镜头净时长。拆段需袋/书/手机连续 |
| 学生坐姿收包 / S01 | A/周然，80–120ticks=4–6秒，前后只能sit | 8秒镜头可容纳动作及余量，但手机通知/持物变化需正确交接，不等于已经可拍 |
| 陈坐姿放手机 / S04 | 40–80ticks，前一步phone_call_sit，后面只能sit | 同段不能又接听新电话或站起；下一次来电可先为声音+反应，真正接听若需要须新状态路径 |
| 路人停录 / E | 30–60ticks，前一步phone，仅filmer | 必须先停止拍摄再帮忙；现有动作不是通用“收手机”指令。与拾物起始位置和手部状态联调 |
| 学生收手机 / S01/S03 | 30–60ticks；phone或phone_sit→匹配收回→idle或sit | 原动作有前后态，不可随意插入取衣循环；按脚本需要安排明确状态 |
| 推离/扶起 / E | 推离6–20ticks，仅陈→老人；老人先idle接recoil；扶起40–100ticks且被support完整覆盖 | 共享事件的接触时间与双方step必须对齐；程序只校验部分时序，不代表身体体积无穿插 |
| 醒来、床边落脚 / S05 | 白名单无专用wake动作；有sit/stand_up不代表完整醒来动画 | 需原Windows资产证明或制作动作适配；不能用瞬间改姿态替代脚落地/站起 |
| 转身、独立视线 / 全片 | walk_to/look_at存在，未证明完整肩髋转身/眼球绑定 | 以头向/躯干节奏实现可见意图；新增眉眼必须有绑定，不向执行Agent许愿 |
| 关投影 / S06 | 无专用角色投影控制动作 | 明确教师动作＋投影材质/图文切换同一tick；不能只后期黑屏遗漏关机行为 |

落地顺序：恢复原动作源→根据实际能力完成一次状态图→逐条生成actor-plan并验证Python/Java一致→录短段→审核→冻结。涉及共享事件的短拾物改动属于新实现，估时须先看原Windows源；不能承诺仅几分钟改一个数字就完成。
